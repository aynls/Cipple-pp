# 独立进程验收

使用当前 Windows CMake 构建生成的服务端与客户端。运行器启动独立进程，通过应用协议和只读 SQLite 查询验证结果，报告包含实际命令和进程输出。 [运行方法](../../doc/delivery.md)

| 场景 | 必须观察到的行为 |
| --- | --- |
| 单节点 | 全量配置、增量、删除和查询正常。进程被强制终止后，已确认的写入可从原文件恢复。 |
| 客户端换主 | 从 Follower 开始的请求可以轮转到 Leader。Leader 停止后，剩余多数派选出新 Leader，已确认的配置仍可读。相同 UUID 和内容只产生一次变更，冲突内容被拒绝。 |
| 多数派丢失 | 原 Leader 的应用端口仍可连接，但孤立副本不能确认写入和线性一致查询。旧 `SyncRequest` 不能绕过 Raft。 |
| 持久订阅换节点 | 同一配置的分发序号在节点间相同。客户端沿已确认的集群游标续传。 |
| 快照追赶 | 保持一个 Follower 离线至 Leader 压缩掉它所需的日志前缀。Follower 重启后安装快照、应用尾部写入，并返回相同的分发序号。 |
| 历史保留 | 被压缩的订阅游标返回最小可用位置。用该位置可回放后续事件。应用了快照的集群关闭并重启后仍可提交。 |
