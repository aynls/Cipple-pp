# 行为与协议

## 确认与恢复

1. **发布确认。** Leader 在多数派持久化日志并应用变更之后回复。结果未知时，发布者可在所属分片内更换节点并重试相同 UUID 和内容。同一分片内，相同 UUID 携带不同内容时请求被拒绝。
2. **查询。** Leader 提交查询命令并在应用时读取值。Follower 以及暂时无法提交的节点返回可重试响应。查询遇到删除或缺失配置时返回空的可见值。
3. **持久订阅确认。** 客户端在同一事务中保存事件和该键的游标，然后回执。重连到同一分片的副本后，从同一位置续传，按实体 UUID 去重。

多数派不可用时发布和查询无法提交。超时或暂不可用的操作可能已经进入日志，恢复多数派后可能提交。订阅只接收本地已经应用的已提交变更。落后副本在连接恢复后追赶 Raft 日志或安装快照。

每个键保留最近 128 条订阅事件。已保存的客户端游标早于保留边界时，从服务端返回的可用位置恢复需要调用者确认。每个客户端订阅库应专用于一个集群。

## 帧和字段

四字节大端长度前缀后的帧体由一字节消息类型、16 字节 RPC UUID 和消息字段组成。帧体最大为 16
MiB。字符串用八字节无符号长度和对应字节表示，整数采用大端序，布尔值占一个字节，0 表示失败或假，1 表示成功或真。未知类型、截断字段或多余字节会使会话关闭。

以下字段均位于 RPC UUID 之后。响应使用对应请求的 RPC UUID。

| 请求                          | 请求字段                                       | 响应                           | 响应字段                                      |
|-------------------------------|------------------------------------------------|--------------------------------|-----------------------------------------------|
| 0 `HeartbeatRequest`          | 无                                             | 1 `HeartbeatResponse`          | 成功标志                                      |
| 2 `SyncRequest`               | 旧版副本消息                                   | 3 `SyncResponse`               | 拒绝（结果字节 2）                           |
| 4 `DeleteRequest`             | 应用、键                                       | 5 `DeleteResponse`             | 成功标志                                      |
| 6 `GetRequest`                | 应用、键                                       | 7 `GetResponse`                | 应用、键、解析出的值、实体数量（i32）及其实体 |
| 8 `PutRequest`                | 应用、键、值                                   | 9 `PutResponse`                | 成功标志                                      |
| 10 `SubscribeRequest`         | 应用、键、游标（i64），订阅绑定当前会话        | 11 `SubscribeResponse`         | 成功标志                                      |
| 12 `UnsubscribeRequest`       | 应用、键                                       | 13 `UnsubscribeResponse`       | 成功标志                                      |
| 14 `IncrementalUpdateRequest` | 应用、键、基底 UUID、操作、值                  | 15 `IncrementalUpdateResponse` | 成功标志                                      |
| 16 `DispatchRequest`          | 实体、分发序号（i64），增量分发另附完整基底    | 17 `DispatchResponse`          | 处理结果                                      |

GET、PUT、DELETE 和增量请求遇到暂不可用时可收到类型 18 `RetryResponse`。响应仅携带原请求 UUID。客户端可在期限内用相同请求轮询已配置的应用端点。

订阅游标 −1 表示实时订阅。0 表示从历史起点回放，正数表示从该序号之后回放。实时分发的序号为 0，持久分发的序号是分片内共享的正数。游标过旧时，订阅请求收到类型 19 `HistoryLostResponse`，字段为最小可用游标（i64）。

对不属于本地分片的键执行查询、写入、订阅或退订时，Server 返回类型 20 `WrongShardResponse`，字段为本机路由表计算出的分片 ID（u32）。客户端将其作为路由错误报告。同一请求遇到换主可以在所属分片内重试。

### 组内转发

| 类型 | UUID 用途 | 字段 |
|------|-----------|------|
| 21 `RelayAdvertise` | 消息 UUID | 监听端口（u32）、可用组员槽位（u32）。均为 0 时只参与接收。 |
| 22 `RelayRoute` | 链路令牌 | 应用、键、地址字符串、端口（u32）。空地址与端口 0 用于授权队长，具体端点用于指派组员。 |
| 23 `RelayStatus` | 链路令牌 | 就绪标志。失败值用于报告或撤销链路。 |
| 24 `RelayHello` | 链路令牌 | 无。组员连接队长时发送。 |
| 25 `RelayDispatch` | 投递 ID | 持久 `DispatchRequest` 的字段、队长是否也接收（布尔值）、令牌数量（u32）、每个目标的 16 字节令牌。 |

Server 收到队长的授权确认后，将端点和令牌发给组员。组员连通并报告就绪后，Server 才把它加入转发名单。队长沿这些连接发送普通 `DispatchRequest`。组员通过自己与 Server 的会话发送 `DispatchResponse`。同一轮可以共享投递 ID，Server 按会话匹配待确认记录。回执只在单调时钟的窗口截止前有效。补发保留实体 UUID、序号和必要的增量基底，并使用新投递 ID。已落盘的客户端按实体 UUID 去重后回执。

实体依次编码自身 UUID、操作名、应用、键、操作负载、版本（i64）和保留的源节点 ID 字段（i32）。`update` 的负载是值，`delete` 的负载为空，
`incremental_update` 的负载是基底 UUID、原子操作和值。原子操作 `add_entry` 拼接字面字符串，`remove_entry` 移除全部字面匹配。

实体版本等于所属分片的 Raft 日志索引，源节点 ID 字段为 0。读取取该键最后一条已应用的变更。当前实体是删除或不存在时，客户端报告配置缺失。
